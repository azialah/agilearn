# IO feature — Excel import/export + PDF export

Implemented the roster import and the export menu for a classroom, wiring the two
placeholder components (`ImportButton`, `ExportMenu`) that were already mounted by
the classroom detail and grades pages.

## What shipped

### Import (`ImportButton.tsx`)

- Dialog with a click-to-browse / drag-and-drop zone accepting `.xlsx` / `.xls`.
- File is read with `xlsx` (`readSheet.ts`) into an array-of-arrays and validated
  by the pure `parseRosterRows` helper.
- Validation preview table: each row shows student no, name and a status badge —
  **new** / **duplicate** / **invalid** — with a reason for the latter two, plus a
  summary count row (and a count of skipped template example rows).
- Tolerates the legacy template layout: a header row and the italic "e.g." notes
  row are auto-detected and skipped, and the `Dela Cruz` / `e.g.` example rows are
  dropped, matching `StudentsImport.php`. Only the first four columns are read, so
  a full 9-column legacy file imports cleanly.
- Confirm inserts only the **new** rows. Inserts run per row (`Promise.allSettled`)
  so one bad row can't sink the batch; the toast reports `inserted / failed`.
  Student/classroom queries are invalidated on success.

### Export (`ExportMenu.tsx`)

Dropdown with three actions, each downloading with a `course_code`-based filename:

- **Roster template (.xlsx)** — header + hint row template (`buildRosterTemplateWorkbook`).
- **Grade sheet (.xlsx)** — roster + one column per activity (grouped period →
  component → category) + per-period lecture/lab grades + component and final
  grades. All grade math comes from `src/lib/grading.ts` using the classroom's
  configured lecture/laboratory weights.
- **Grade report (.pdf)** — client-side via `pdf-lib`: classroom header (course
  name / code / year / block), a bordered student table with lecture / laboratory
  / final grades, page footers with the generated date and page numbers. Paginates
  automatically for long rosters.

Read-only data comes from the existing query hooks (`useClassroom`, `useStudents`,
`useGradebookStructure`, `useScores`); the batch insert lives in this feature
(`mutations.ts`).

## Pure helpers + tests

`parsing.ts` holds the framework-free logic — `parseRosterRows`, `slugifyCode`,
`buildFilename` — covered by `parsing.test.ts` (14 cases: header/notes skipping,
example-row dropping, missing-name validation, existing + in-file duplicate
detection, blank-row handling, wide-file column limiting, cell coercion, and the
filename builder).

## Notes / deviations

- The current `students` table only stores `student_no` / names, so the generated
  roster template is four columns (not the legacy nine); grades are computed from
  the gradebook rather than stored per student.
- SheetJS community edition writes structure and column widths but not cell
  fills/fonts (Pro-only), so the exported sheets match the legacy layout and
  widths rather than its colors. Freeze panes are likewise unsupported and were
  left out.
